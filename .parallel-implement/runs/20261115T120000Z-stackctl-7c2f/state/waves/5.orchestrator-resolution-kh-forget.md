# Wave 5 — orchestrator resolution: kh_forget corrupts retained bindings

Escalation `w5-tests-20261115T063349Z-kh-forget-corrupts-store` (from
`w5-tests`, `blocking: true`) reported that `kh_forget()` rewrites every
*retained* entry as only its instance-id alias, dropping the key type and key
material. The contract suite failed honestly at
`tests/contract/contract_test.c:415` ("surviving binding keeps its key
material") after pinning `i-abc` + `i-other` and forgetting `i-abc`.

Reply written: `inbox/w5-tests/w5-tests-20261115T063349Z-kh-forget-corrupts-store.md.reply.md`
(`disposition: done`).

## Root cause

`core/knownhosts/knownhosts.c:kh_forget()` parsed each line in place with
`split_first(cursor, &first)`, which overwrites the first whitespace delimiter
with `'\0'`. It then copied `cursor` (now only the `<instance-id>` field) into
the new store. Retained lines therefore lost `<key-type> <key-material>`:
`kh_bound()` still matched the bare id, but SSH verification could not use the
entry, and a later `kh_pin()` for that id saw a key-material conflict and
returned EPERM. This broke launch's replace path (pin new instance, forget old),
which truncated the new binding and made the next launch for that id fail with
exit 3.

## Fix

- Added `line_first_field_is(line, instance_id)` — a non-mutating matcher that
  checks whether the first whitespace-delimited field equals the id.
- `kh_forget()` now computes `drop` with that matcher and copies the untouched
  line verbatim (id + key type + key material) when retaining it, dropping only
  the matched line. The atomic temp+fsync+rename write path and all other file
  semantics are unchanged. No public interface change.

## Files changed

- `core/knownhosts/knownhosts.c` — non-mutating first-field match; verbatim
  copy of retained lines in `kh_forget()`.
- `core/knownhosts/knownhosts_test.c` — regression test: pin two bindings,
  forget one, assert the retained line keeps id+key material byte-for-byte,
  and re-pin retained ids without EPERM.
