### 1. VERSION resolution — FAIL

- [major] `core/cli/dispatch/dispatch.c:266,355-370` — runfiles probing only tries literal `_main` and `stackctl`. Under bzlmod, an external module's runfiles directory is its canonical name (`stackctl+`/`stackctl+0.1.0`), not `stackctl`. The ancestor fallback does not save this because `/proc/self/exe` under `bazel run` points into `bazel-out/...`, which is not under the runfiles root, so `read_version_between()` (`:277`) returns 0. Thus the documented consumed wrapper (`bazel run //deploy/aws:stackctl`, README:66-69) can print `unknown` while `<canonical>/VERSION` exists. Fix: derive the executing repo dir from `exe` relative to the runfiles root, or use repo-mapping/runfiles resolution rather than hardcoded names.
- [minor] `core/cli/dispatch/dispatch_test.c:253-305` simulates only `_main`/`stackctl`, so it cannot catch the external-canonical case it claims to model; `test_version_runfiles_workspace_only` likewise hardcodes `stackctl`.
