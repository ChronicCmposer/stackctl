# Wave 1 — Amendments 3 and 4 effectuation

Appended Amendments 3 (lint policy, all languages, gates verification) and 4
(hermetic tooling only) to CONTRACT.md, then built the hermetic lint gate they
require. `AGENTS.md` now carries the single `build-policy` fenced block.

cppcheck publishes no Linux binary, so its sha256-pinned release source tarball
is compiled by Bazel (`@cppcheck//:cppcheck`). The binary locates `std.cfg`
relative to `/proc/self/exe`, so `lint.sh` runs a copy of the binary beside the
Bazel-fetched `cfg/` files (`@cppcheck//:cfg`). No tool is read from PATH.

## Targets (`tools/lint/BUILD.bazel`)

| Target | Behaviour |
| --- | --- |
| `//tools/lint:lint-c` | cppcheck over workspace `*.c`/`*.h` |
| `//tools/lint:lint-starlark` | buildifier `-mode=check -lint=warn -warnings=all` |
| `//tools/lint:lint-shell` | shellcheck `--severity=warning` over `*.sh`/`*.bash` |
| `//tools/lint:lint-yaml` | yaml_check over `*.yaml`/`*.yml` |
| `//tools/lint:lint-markdown` | markdown_check over `*.md` |
| `//tools/lint:lint` | aggregate of all five; non-zero on any violation |

Discovery is glob-based over the workspace (prunes `.git/`,
`.parallel-implement/`, `bazel-*`). Vendored upstream sources are in Bazel
external repositories and are therefore never linted; only our `third_party/`
overlay files are. New modules are covered automatically. Targets are
`bazel run` entry points; workspace-wide source discovery is not
sandbox-compatible, so no `bazel test` lint wrapper is provided.

## Hermeticity notes

- Every linter is fetched/built by Bazel and invoked through `bazel run`; none is
  host-installed.
- Python is not used at all (yamllint/markdownlint substituted by in-repo C
  checkers), so no rules_python toolchain is needed.
- The driver uses POSIX shell utilities (`find`, `cp`, `mktemp`) as glue only;
  the analysis itself is performed by the hermetic tools.
- `core/config` and `core/crypto` now compile with `-Wall -Wextra -Werror` as
  the C compiler gate required by Amendment 3.
