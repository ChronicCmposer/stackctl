## Scope summary per lane

### w4-verbs-instance (launch / status / terminate)

- Launch: S3 manifest fetch + sha verify against the stack
  `stackctl:release-sha` tag + member selection using `instance_manifest_select`;
  pass selected member/sha and a non-empty variant to the box; bounded
  `GetConsoleOutput` + `ssh-keyscan` polling honoring `--ssh-timeout`; remote rc
  path + bundle staging + `reconnect_argv`; pinned AMI from the stack only (no
  config fallback); record replaced instance ids in the launch record and
  operations.log; check `state_launch_record_append`; align the manifest format
  with the deploy writer.
- Status: identity guard (exit 3), known-hosts bindings report, release-member /
  garbage-prefix listing, state-dir-writable check.
- Terminate: validate target state before `--instance-id` termination.

### w4-verbs-stack (provision / deploy / refresh-ami)

- Provision: implement the IAM key lifecycle (mint/rotate, exactly-one
  invariant, prune-before-create, ini profile write + timestamped backup,
  `InvalidClientTokenId` 6x retry) consuming `core/iam`; infer the region
  variant from `--region`, not from file existence.
- Deploy: publish read-back verification (S3 HEAD + read-back) before recording
  the release; prune stage (keep 10, protect pinned/previous/just-uploaded,
  delete manifest-less garbage older than 24 h); `--skip-build` against an
  immutable tag exits 3; live-instance count/preview; align manifest format with
  the launch parser.
- refresh-ami: make the `.env` / `.env.example` dual-write atomic (no
  half-applied state).
- Cross-cutting: escape `repo_root` in shell interpolation; do not call
  `aws_request` directly.
