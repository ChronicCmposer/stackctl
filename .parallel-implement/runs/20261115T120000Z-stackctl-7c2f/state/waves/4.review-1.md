## (i) Correctness vs contract/spec — FAIL

- [critical] launch never resolves the release manifest/member: `--variant` parsed but unused (`core/cli/launch/launch.c:822`); `STACKCTL_VARIANT` always empty (`launch.c:262`); no S3 manifest fetch, no sha verify against `stackctl:release-sha`, no member selection/sha passed to box — spec §7.3/§4; `instance_manifest_select` exists but never called (`core/cli/launch/common/instance_util.c:333-346`); `core/s3` declared dep unused in launch.c.
- [major] launch host-key flow lacks bounded polling: GetConsoleOutput called once (`launch.c:542-546`), ssh-keyscan once (`launch.c:548-553`); `--ssh-timeout` parsed but unapplied (`launch.c:833-837`); console-absent therefore nearly always TOFU, defeating the verification rule.
- [major] remote rc/reconnect contract missing: setup command writes no `/run/stackctl-setup.<nonce>/rc`, no bundle staging (`launch.c:238-285`); `sshc_sentinel_spec` sets `remote_rc_path=NULL`/`reconnect_argv=NULL` (`launch.c:640-649`), making the exit-255 reconnect-once read impossible (`core/ssh/ssh.h:82-84`).
- [major] pinned AMI falls back to config: under `pinned`, AMI must come from stack `AmiId`, never config; `launch.c:112-124` falls back to `cfg.ami_id_*` when the stack param is absent.
- [major] replaced-instance recording dropped: `launch.c:709,746-767` builds a comma list then discards it `(void)replaced`; launch record omits `replaced` (`launch.c:770-781`; field exists `core/state/state.h:48`); spec requires replaced ids in launch record + operations.log.
- [critical] provision key lifecycle absent: `prod_keys` only calls STS and prints a rotation warning (`core/cli/provision/provision.c:146-194`); no IAM key mint/rotate, no exactly-one/prune-before-create, no ini profile write/backup, no `InvalidClientTokenId` 6x retry (`provision.c:239-256`).
- [major] provision rejects wrong condition: `region_variant` inferred from `.env.<region>` file existence, not `--region` (`provision.c:843-848`); a multi-region project's primary `.env` run would be refused.
- [major] deploy skips publish read-back: new release path calls `publish_release` then records on stack without S3 HEAD/read-back verification (`core/cli/deploy/deploy.c:1184-1193`; publish uploads only `deploy.c:724-808`); spec §7.2 requires verify-before-record.
- [major] deploy has no prune stage: §4/§7.4 step 5 (keep 10, protect pinned/previous/just-uploaded, delete >24h garbage) entirely absent.
- [minor] `--skip-build` against already-immutable tag should exit 3 (`deploy.c:1114-1122,1169-1177`); live-instance count/preview absent (`deploy.c:1313-1320`).
- terminate/startstop/refresh-ami conform well; terminate `--instance-id` does not validate target state before terminate (`core/cli/terminate/terminate.c:127-144`) [minor].
- status omits identity guard (exit-3 path nonexistent), known-hosts bindings report, release-member/garbage-prefix listing, state-dir-writable check (`core/cli/status/status.c:245-275,560-579`) [major/minor].
