## Cited defects

### (i) Correctness vs contract — FAIL

- [major] Authoritative DNS lookup is not authoritative-only. `cares_query_a` resolves through `resolve_ipv4()` -> `ares_getaddrinfo()` (`core/dns/dns_cares.c:319,204-228`); ares_getaddrinfo consults hosts-file and applies RFC-6724 sorting instead of issuing a raw A query on the ARES_FLAG_NORECURSE + ARES_OPT_SERVERS channel. Spec §5.7. Fix: `ares_query(..., ns_t_a)` + `ares_parse_a_reply` on the NORECURSE channel.
- [major] NS discovery injects the queried domain as a nameserver: `ns_callback` calls `add_ns_name(result, host->h_name)` (`dns_cares.c:167`); per `ares_parse_ns_reply` nameservers are in `h_aliases`, not `h_name`. First NORECURSE A query goes to the domain's own A-record host (`core/dns/dns.c:141-155`).
- [major] Infra ingress ignores configured ports/CIDRs: `TcpIngress`/`UdpIngress` open only `!Select [0, !Ref IngressTcp|Udp]` and hardcode `CidrIp: 0.0.0.0/0` (`deploy/stackctl-infra.yaml:177-192`); spec §3:200 defines INGRESS_TCP/UDP as comma lists of `port[:cidr]` and §6.2:831-832. Extra ports dropped, CIDR ignored -> world-wide.
- [major] §6.3 checker fails open on long-form intrinsics: `check_iam_node` uses `scalar_count()` (`deploy/check/template_check.c:642-664,741-756`) which returns 0 for NODE_MAP, so `Action: {Fn::If:...}` / `Resource: {Fn::Sub:...}` are never validated; violates fail-closed guarantee (`template_check.h:9`, contract L115-120).
- [minor] `aws_init` strips AWS_* only after successful credential load (`core/aws/aws.c:189-192,224`); ambient vars survive ENOENT.
- [minor] `aws_init` hand-rolls INI parsing instead of core/ini (`aws.c:5-6,50-129`).
- [minor] `InvalidSignatureException` classified as clock skew (`core/aws/resp.c:139-144`).
- [minor] Instance-role cert policy unconditional (`deploy/stackctl-operator.yaml:67-85`); spec §6.1 says per enabled bucket module.
