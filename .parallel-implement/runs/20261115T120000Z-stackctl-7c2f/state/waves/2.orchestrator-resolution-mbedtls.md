## Diagnosis
`bazel build //...` linked curl consumers against undefined
`mbedtls_x509_crt_parse_file`, `mbedtls_x509_crt_parse_path`,
`mbedtls_pk_parse_keyfile`, `mbedtls_x509_crl_parse_file`,
`mbedtls_pk_write_pubkey_der`. The hand-written minimal config omitted the
source-guard macros:
- `MBEDTLS_FS_IO` guards the cert/key/CRL file + path parsers
  (`library/x509_crt.c`, `library/x509_crl.c`, `tf-psa-crypto/extras/pkparse.c`).
- `MBEDTLS_PK_WRITE_C` guards `tf-psa-crypto/extras/pkwrite.c`
  (`mbedtls_pk_write_pubkey_der`) and requires `MBEDTLS_ASN1_WRITE_C`
  (`tf_psa_crypto_check_config.h`).
- Split-config subtlety: the X.509 TU reads `mbedtls_config.h`; the TF-PSA
  PK TU reads only `crypto_config.h`, so `MBEDTLS_FS_IO` is needed in both.

## Fix (third_party/mbedtls/** only; no vendored C sources touched; no curl feature disabled)
- `configs/mbedtls_config.h`: `+#define MBEDTLS_FS_IO`
- `configs/crypto_config.h`: `+#define MBEDTLS_ASN1_WRITE_C`,
  `+#define MBEDTLS_PK_WRITE_C`, `+#define MBEDTLS_FS_IO`
- `config_presence_test.c`: compile-time asserts for `MBEDTLS_FS_IO`,
  `MBEDTLS_PK_PARSE_C`, `MBEDTLS_PK_WRITE_C`, `MBEDTLS_ASN1_WRITE_C`.
Profile stays client-only (no server/DTLS/LMS).
