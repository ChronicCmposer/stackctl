## Finding

`resolve_emitted_name` (`deploy/check/template_check.c:1812-1819`) delegates scalar name evaluation to `resolve_name_piece` (`:1617-1641`), which returns the raw `${...}` text for an unknown variable instead of signalling failure. `find_ci_identities` (`:1861-1870`) therefore does not count the name as unresolved, and the fail-closed diagnostic (`:2148-2152`) never fires. Counterexample: `UserName: !Sub ${ProjectName}-ci${CiSuffix}` with an over-broad non-canonical reader escapes rule 4. This contradicts the attempt-3 claim that ANY declared-but-unresolvable name fails closed. D20's fix covered only the explicitly named unresolvable shapes; this is the same class recurring, so this record supersedes D20.
