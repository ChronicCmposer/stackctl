## Finding

D27's residual bypass survives at entry level. `section_is_plain_sequence` correctly rejects a *section* node that is not a plain sequence, but `add_ci_membership_groups` resolves each `UserToGroupAddition.Properties.Users` entry via `section_names_ci_identity` (`deploy/check/template_check.c:1989-1996`), which only recognises scalar entries that name a CI identity.

When `Users` is a plain `NODE_SEQ` and an entry is an intrinsic (`- !If [...]`, `- Fn::If: ...`) or a nested list, the entry cannot be resolved, `section_names_ci_identity` returns 0 for it, and the caller `continue`s (`:2074-2076`). The whole addition, its `GroupName`, and the joined group are then dropped from the CI identity set, so that group's over-broad `s3:PutObject` policy is never inspected — a CONTRACT rule-4 bypass.

Fix direction: resolve the plain-sequence `UserToGroupAddition.Properties.Users` per entry. Any entry that is a map/intrinsic or a nested sequence must be a violation (fail closed). Long-form `Ref` entries to existing identities remain accepted, and non-CI statically resolvable entries remain accepted.
