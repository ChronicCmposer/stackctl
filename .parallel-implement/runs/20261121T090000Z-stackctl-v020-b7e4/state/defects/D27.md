## Finding

`scalar_count` returns 0 for `NODE_MAP`, so property-level long-form intrinsic maps are silently skipped in membership and attachment handling. The same root class as D1 — fixed for `Action`/`Resource` via `resolve_node` but not for membership/attachment — survives in four sites:

- `AWS::IAM::User.Properties.Groups` written as an `Fn::If`/`Ref` map (`deploy/check/template_check.c:2075-2076`) is never iterated, so the joined group is never added to the CI set and that group's over-broad `s3:PutObject` is never inspected (CONTRACT rule 4 bypass).
- `UserToGroupAddition.Users` written as a map (`:2054`) skips the whole addition and `GroupName` is never checked.
- `policy_names_ci_identity` (`:2091-2100`) and `check_unresolved_policy_principals` (`:2154-2188`) have the same blind spot for policy-attachment sections.

Fix direction: every membership/attachment section or entry that is a map/intrinsic or otherwise not a plain sequence of statically resolvable names must be a violation (fail closed); no silent skip.
