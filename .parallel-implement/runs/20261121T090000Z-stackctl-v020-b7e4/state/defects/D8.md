## Finding

Rule 4 is still keyed to the CI identity's LOGICAL ID. `find_ci_identity_name` (`deploy/check/template_check.c:1570-1581`) returns the resource key of the `${ProjectName}-ci` user/role, and `is_ci_reader_policy` (`:1583-1592`) plus `policy_attachment` (`:1699-1708`) match only policies whose own `Users`/`Roles`/`Groups` name that logical id. A non-canonical reader policy attached through the CI identity's `ManagedPolicyArns`, or attached by NAME (`!Sub ${ProjectName}-ci`), therefore escapes rule 4 entirely, and the generic IAM walk accepts `s3:PutObject` on the own object ARN. This is the residual of D7 and a runtime fail-closed gate bypass of CONTRACT rule 4.
