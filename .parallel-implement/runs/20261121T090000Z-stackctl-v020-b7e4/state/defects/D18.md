## Finding

`add_ci_membership_groups` (`deploy/check/template_check.c:1931-1972`) discovers CI membership only from `AWS::IAM::UserToGroupAddition`. `AWS::IAM::User.Properties.Groups` is unmodeled, so a group referenced directly on the CI user is not treated as a CI-reader identity and its attached policies escape rule 4. A CI user's group-attached `s3:PutObject` on the own object ARN, or `s3:GetObject` on another project's bucket, can pass the gate.
